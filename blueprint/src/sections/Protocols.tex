\section{List of the Protocols}

Protocols will be introduced as a set of properties to
satisfy given in natural language. Then, an implementation
taken from the literature will be presented as pseudo-code. Finally, a PLTS
encoding of these properties will be provided to which we aim
to reduce the implementation. For readability, pseudo-code and PLTS encoding
will be relegated to Appendix.

\paragraph{Common Notation.}
Without loss of generality, we can assume that each process has a unique
identifier ranging from 1 to $n$. The set of identifiers is denoted $[n]$.
The number of faulty processes is bounded by a threshold denoted $f$ and
the set of faulty processes is denoted $F$.

\subsection{Asynchronous Byzantine Agreement (\textsf{ABA})}
\textsf{ABA} is a canonical protocol where processes must
agree on a common output.
Processes start with a bit $\{0,1\}$ and may return a bit.
Its interface is composed of a $call$ and a $return$ statement.
A program implements \textsf{ABA} if it satisfies three
properties: Validity, Agreement, Almost-Sure Termination.
\begin{itemize}
    \item Validity: if a correct process returns $b$ then a correct process had $b$ as input.
    \item Agreement: if two correct processes return, then their outputs are equal.
    \item Almost-sure Termination: if $n-f$ correct processes take part in the protocol then, with
    probability 1, all correct processes will eventually return.
\end{itemize}

\begin{implementation}[from \cite{Abraham2022Efficient}]
    \label{impl:ABA}

    This implementation relies on \textsf{GBCA} and \textsf{WCC}. It proceeds
    in asynchronous rounds in which processes start by performing \textsf{GBCA},
    then call \textsf{WCC}. They use their input as for the first round then
    update it based on the outcome of \textsf{GBCA} and \textsf{WCC}. The
    pseudo-code is provided in Algorithm \ref{alg:ABA}.
\end{implementation}

    \label{ABA:Core}
    \lean{ABA.Core}

    The PLTS encoding Algorithm \ref{alg:ABA} is denoted \textsf{ABA.Core}.
    Its adversary is omniscient.
\end{definition}

    \lean{ABA.Spec}

    We call it \textsf{ABA.Spec} and its adversary is omniscient.
    It contains a probabilistic transition whose outcome depends on an unspecified
    $\epsilon$ which corresponds to the goodness of \textsf{WCC}.
\end{specification}

    \label{ABA:Impl}
    \lean{ABA.Impl}

    Since the adversaries of \textsf{ABA.Core} and \textsf{GBCA.Impl}

\end{definition}

\subsection{Graded Binding Crusader Agreement (\textsf{GBCA})}

Processes start with a binary input $\{0,1\}$ and may return a value in
$\{(0,A), (0,B), (\bot,C), (1,B), (1,A)\}$.
A program implements \textsf{GBCA} if it satisfies four properties: Validity, Graded Agreement,
Binding, Termination.
\begin{itemize}
    \item Validity: if a correct process does not return $(b,A)$ then a correct process had $1-b$
    as input.
    \item Graded Agreement: if two correct processes return $(b,X)$ and $(b',X')$ then
    $b = 0 \implies b' \ne 1$ and $X = A \implies X' \ne \bot$.
    \item Binding: when a correct process returns then a bound value $b$ is defined and, in all
    extensions of the execution, correct processes do not return $(1-b,B)$ or $(1-b,A)$.
    \item Termination: if $n-f$ correct processes take part in the protocol then all correct
    processes will eventually return.
\end{itemize}

\begin{implementation}[from \cite{Abraham2022Efficient}]
    \label{impl:GBCA}

    This implementation consists of 4 rounds of message exchange.
    It does not rely on any sub-protocol and its algorithmic core
    idea is quorum intersection. The pseudo-code can be found in
    Algorithm \ref{alg:GBCA}.
\end{implementation}

    \label{GBCA:Impl}
    \lean{GBCA.Impl}
    %\leanok

    The PLTS encoding Algorithm \ref{alg:GBCA} is denoted \textsf{GBCA.Impl}.
    Its adversary is omniscient.
\end{definition}

\begin{specification}
    \label{GBCA:Spec}
    \lean{GBCA.Spec}
    %\leanok

    The PLTS encoding of \textsf{GBCA} is provided in Transition System \ref{PLTS:GBCA}.
    It is called \textsf{GBCA.Spec} and its adversary is omniscient.
    Since the branching property is not preserved by our simulation,
    we enhance the interface of \textsf{GBCA} to include the bound value in the return
    labels. This way, the binding property becomes linear.
\end{specification}

\subsection{Weak Common Coin (\textsf{WCC})}

Processes start with no input and may return a bit.
A program implements \textsf{WCC} if it satisfies three properties: $\epsilon$-Goodness,
Unpredictability, Termination.
\begin{itemize}
    \item $\epsilon$-Goodness: with probability $\epsilon$, all correct processes return 0
    (resp.\ 1).
    \item Unpredictability: until $f+1$ processes have called \textsf{WCC}, all outcomes are still
    possible.
    \item Termination: if $n-f$ correct processes take part in the protocol then all correct
    processes will eventually return.
\end{itemize}

\begin{implementation}[simplified from \cite{Freitas2022Distributed}]
    \label{impl:WCC}

    The implementation of \textsf{WCC} relies on \textsf{SRSD} and \textsf{Gather}.
    The idea is to randomly assign a number to each process
    then select a subset of processes
    and return based on the value assigned to these processes.
\end{implementation}

\subsection{\textsf{Gather}}

Processes start with an input $x \in X$ and may return a partial function
$f: Proc \rightharpoonup X$ presented as a subset of $Proc \times X$.
A program implements \textsf{Gather} if it satisfies four properties: Validity, Agreement, Binding
Common Core, Termination.
\begin{itemize}
    \item Validity: if a correct process returns $f$ and $f(q)$ is defined and $q$ is correct then
    $f(q)$ is $q$'s input.
    \item Agreement: if two correct processes return $f$ and $g$ then $f(q)$ and $g(q)$ are equal
    or one of them is undefined.
    \item Binding Common Core: once a correct process has returned, there exists
    $S \subseteq Proc$ of size at least $n-f$ such that every $f$ returned by a correct process in
    the future is defined on $S$.
    \item Termination: if $n-f$ correct processes take part in \textsf{Gather} then all correct
    processes will eventually return.
\end{itemize}

\begin{implementation}[taken from \cite{Attiya2025Beyond}]
    \label{impl:Gather}

    This implementation relies on \textsf{BRB} and is non-probabilistic.
    Basically, each process will broadcast its input and then
    three rounds of message exchange allow processes to decide
    which broadcasted inputs they should return.
\end{implementation}

\subsection{Single Random Secret Draw (\textsf{SRSD})}
The \textsf{SRSD} protocol is actually a pair of protocols: Assignment \textsf{Asg} and
Reconstruction \textsf{Rec}.
For each instance, a process is designated beforehand as the owner;
all processes know who the owner is. Assignment assigns a random value to the
owner such that the assigned value is unknown to all. Reconstruction reveals the
assigned value to processes. A correct implementation of \textsf{SRSD} should
satisfy five properties.
\begin{itemize}
    \item Assignment Termination: if all correct processes call \textsf{SRSD}.\textsf{Asg},
    then all correct processes will eventually terminate \textsf{SRSD}.\textsf{Asg}.
    \item Assignment Totality: if a correct process terminates \textsf{SRSD}.\textsf{Asg}
    then all correct processes will eventually terminate \textsf{SRSD}.\textsf{Asg}.
    \item Randomness: the return value of \textsf{SRSD}.\textsf{Rec} follows the uniform
    distribution.
    \item Secrecy: if no correct process has called \textsf{SRSD}.\textsf{Rec} then the adversary
    has no information about the return value of \textsf{SRSD}.\textsf{Rec}.
    \item Retrieval Termination: if all correct processes call \textsf{SRSD}.\textsf{Rec} then all
    correct processes will eventually terminate \textsf{SRSD}.\textsf{Rec}.
\end{itemize}

\begin{implementation}[adapted from \cite{Freitas2022Distributed}]
    \label{impl:SRSD}

    The implementation relies on \textsf{AVSS} and \textsf{BRB}. Each process
    randomly picks a number and shares it among all processes using \textsf{AVSS}.
    Then, the owner broadcasts a set of processes and all processes reconstruct
    the secret of these processes and return their sum.

\subsection{Byzantine Reliable Broadcast (\textsf{BRB})}

Each instance of \textsf{BRB} has a designated \emph{leader} with an input message $m$ and
processes may return a received message.
A program implements \textsf{BRB} if it satisfies three properties: Validity, Totality and
Agreement.
\begin{itemize}
    \item Validity: if the leader is not corrupted then all correct processes must return its
    input.
    \item Agreement: if two correct processes return then they return the same value.
    \item Totality: if a correct process returns then all correct processes eventually return.
\end{itemize}

\subsection{Asynchronous Verifiable Secret Sharing (\textsf{AVSS})}

The \textsf{AVSS} is actually a pair of protocols: Sharing \textsf{Sh} and Reconstruction
\textsf{Rec}.
Each instance has a designated process called the dealer which is known by all processes.
The dealer starts \textsf{Sh} with a secret value which it divides into shares
and hands one to each process. During \textsf{Rec}, processes gather shares
from other processes to reconstruct the original secret.
A program implements an $\epsilon$-correct \textsf{AVSS} if it satisfies three properties:
Termination, Correctness, Secrecy.
\begin{itemize}
    \item Termination:
    \begin{itemize}
        \item if the dealer is correct and has called \textsf{AVSS.Sh}
        then all correct processes will eventually terminate \textsf{AVSS.Sh};
        \item if a correct process has terminated \textsf{AVSS.Sh}
        then all correct processes will eventually terminate \textsf{AVSS.Sh};
        \item with probability $1-\epsilon$, if all correct processes have terminated
        \textsf{AVSS.Sh} and called \textsf{AVSS.Rec}
        then all correct processes will eventually terminate \textsf{AVSS.Rec}.
    \end{itemize}
    \item Correctness: Once a correct process has terminated \textsf{AVSS.Sh},
    there exists $x \in X$ such that,
    \begin{itemize}
        \item if the dealer is correct then it has called \textsf{AVSS.Sh} with $x$;
        \item with probability $1-\epsilon$, no correct process will terminate \textsf{AVSS.Rec}
        with a value different from $x$.
    \end{itemize}
    \item Secrecy: if the dealer is correct and no correct process has called \textsf{AVSS.Rec}
    then the adversary has no information about the future retrieved value.
\end{itemize}
Some properties always hold while others hold with probability $1- \epsilon$.
The specification of \cite{Canetti1993Fast} states that all properties hold with
probability $1-\epsilon$, but it seems that the specification can be strengthened.
For instance, if the dealer is correct then the committed value can be chosen to be
its input to \textsf{AVSS.Sh}. Moreover, the second point of termination should also
always hold because correct processes broadcast a certificate to terminate \textsf{AVSS.Sh};
thus, if one correct process gets it then all of them will get it.

Our proof will stop at this level of abstraction, meaning that all considered
implementations will be correct up to the correctness of their underlying \textsf{AVSS}.
Efficient implementations of \textsf{AVSS} enter the realm of cryptography, which
is not the main target of our methodology. A possible implementation could have
been the one from \cite{Canetti1993Fast}.

\begin{specification}
    \label{AVSS:Spec}
    \lean{AVSS.Spec}
    %\leanok

    The PLTS encoding of \textsf{AVSS} is provided in Transition System \ref{PLTS:AVSS}.
    We call it \textsf{AVSS.Spec} and its adversary should not see the secret
    input unless the dealer is Byzantine.
    To encode the commitment as a linear property, the committed value is provided
    when \textsf{AVSS.Sh} returns.
    It uses the same trick as \textsf{WCC} and \textsf{SRSD} to encode secrecy.
    Since secret values are contained in the interface of \textsf{AVSS}, this
    specification must be expressed with partial information.
\end{specification}
